## Decisions Made

- **The allowlist was not widened.** Four of the seven shared paths are textbook entries under the
  list's own rule; adding them would have made the run pass. The list's header forbids exactly that,
  and the list is a decision recorded in the contract, so the disposition is the owner's.
- **Checkout identity is read from `CNAME`, not from argument order.** `CNAME` is on the allowlist as
  a path and holds a different hostname on each side, which makes it the one file that can tell the
  trees apart. This also refuses the same checkout passed twice — the `cd ""` hazard
  `04.2-split-env.sh` exists to prevent, in the auditor rather than only in the shell.
- **The guard moved onto the post-exclusion lists.** See Deviations.
- **Not wired into CI, deliberately** (D30). The check needs two checkouts and a runner has one. The
  half that needs only one tree — the pinning case — runs in CI in both repositories on every push.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing Critical] The non-empty guard checked the raw file list, not the comparable one**

- **Found during:** Task 2, by the pinning case, before the wiring
- **Issue:** `assertTreesNonEmpty` ran on the raw `git ls-files` output. A checkout holding nothing
  but `.planning/` files is non-empty by `length` and empty by SUBJECT — every path is dropped by the
  exclusion before the comparison — so it passed the guard and the run compared nothing and reported
  success. That is precisely the failure the guard exists to prevent, one exclusion removed.
- **Fix:** `auditSharedPaths` now filters first and guards the filtered lists; the message names the
  exclusion. The case asserts both forms, so the hole cannot reopen.
- **Verification:** Case red before the fix (`a tree whose every path is excluded must be refused:
  expected [Function] to throw an error`), green after, in both repositories.
- **Committed in:** `3d7bf81` (HAOO), `b23f3f9` (ZPH)

**2. [Rule 3 - Blocking] The `.mjs` auditor is imported through a computed specifier**

- **Found during:** Task 2
- **Issue:** `tsconfig.app.json` includes only `src`, so a literal `../../scripts/*.mjs` specifier is
  an unresolved module to `tsc --noEmit` and the typecheck gate would have gone red.
- **Fix:** `await import(pathToFileURL(AUDITOR_PATH).href)` — still a direct module import of the
  checking functions, which is what the auditor's `import.meta.url` guard exists to permit, and not a
  CLI round-trip. The reason is stated at the call site.
- **Verification:** `npm run typecheck && npm run lint` exit 0 in both.
- **Committed in:** `3d7bf81`, `b23f3f9`

**3. [Deviation - TDD ordering] Task 1 carries `tdd="true"` but the plan assigns its tests to Task 2**

- Task 1's `<files>` lists only `shared-scaffold.txt` and the auditor; the pinning case lives in
  `build-output.test.ts`, which is Task 2's file. Task 1 was therefore committed as `feat` with its
  behaviour verified by its own `<verify>` block, and the RED→GREEN cycle ran in Task 2, where it
  immediately earned its keep by catching deviation 1. Recorded rather than worked around.

## Issues Encountered

**Three acceptance criteria are unsatisfiable as written. None was worked around. All are recorded
as D31, D32 and D33, with the measured figures.**

1. **D31 — the intersection outside the nineteen-path allowlist is 5, not 0** (7 once this plan
   commits its own two byte-identical artifacts). The contract's `# must print nothing` was written
   before either tree existed. Four of the seven — `index.html`, `scripts/assert-phase1-red.mjs`,
   and the auditor's own two files — are toolchain scaffolding the enumeration missed, and are
   allowlist candidates under the list's own rule. Three — `src/App.tsx` and the two suites — are
   path collisions with fully divergent content, which SPLT-01 does not forbid: the requirement is
   about content ownership, and the check measures path collision.
2. **D32 — the ZERO-PAPER HUB positive half measures 11 files against an expected 2**, and the
   auditor flags itself and its own allowlist. Even the narrowest honest reading (the literal
   `haoo.online`, non-comment content only) yields 4 — the two expected plus the two suites whose
   whole job is to police the product's absence. A criterion forbidding a guard from naming what it
   guards against is self-defeating.
3. **D33 — consequently `npm run verify:disjoint` exits 1 in both repositories**, so the four
   `<verify>` commands that run the auditor against the real checkouts are unsatisfiable. Both of the
   plan's prohibitions were honoured: nothing was added to the allowlist, and no check was softened.

**SPLT-01 is therefore NOT marked complete.** `requirements-completed` is empty by intent.
